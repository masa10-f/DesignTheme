# 配色の理論と手順

種色 3 つ（ベース・アクセント・サブ）が与えられたあと、残りの配色をどう決めるかをまとめる。理論、手順、数値の根拠を扱う。

実装は次の 3 つ。

- [scripts/derive.py](../scripts/derive.py)（導出）
- [scripts/themelib.py](../scripts/themelib.py)（種色の判定）
- [scripts/check.py](../scripts/check.py)（検査）

数値を変えるときは、コードとこの文書を同時に直す。

## 1. 前提と目標

- **種色はユーザーが与える。** この文書は、その後の手順を扱う。
- **白い背景が前提。** スライド、論文・ポスターの図、Web ページを想定している。暗い背景は対象外。
- 目標は次の 4 つ。
  1. 文字と線が読める（WCAG のコントラスト基準を満たす）
  2. 種色の印象を保つ（種色の値は変えない）
  3. 誰がやっても同じ結果になる（手順が決まっている）
  4. 由来を記録し、検査できる
- **見た目の良し悪しは自動では判定しない。** 色相の調和などは、プレビューで人が確認する。

## 2. ワークフロー（新しいテーマを追加するとき）

1. ユーザーから、種色 3 つとテーマの名前を受け取る。
2. 書き込まずに判定を見る。

   ```sh
   python scripts/derive.py NN <slug> --name "<表示名>" \
       --base <色名>=#RRGGBB --accent <色名>=#RRGGBB --sub <色名>=#RRGGBB --dry-run
   ```

3. **基準（[4 章](#4-種色の役割と基準)）を満たさない種色があれば、提案をユーザーに示して決めてもらう。** 提案は、同じ色相で明度だけを変えた色。
   - 提案を採る場合は、表示されたコマンドで実行する。
   - そのまま使う場合（ユーザーがそう決めたときだけ）は `--keep-seeds` を付ける。判定と提案は `notes` に残る。
   - 判定を満たさない種色があると、`--dry-run` も `--keep-seeds` もなければ derive.py は書き込まずに止まる。
4. `--dry-run` を外して書き込む。README のひな形ができるので、TODO（テーマの説明、場面ごとのルール）を埋める。
5. `python scripts/check.py && python scripts/build.py` を実行し、プレビューを確認する。プレビューは `themes/NN-<slug>/README.md`、または GitHub 上のそのフォルダで見られる。特に次を見る。
   - 帯の上の文字（`on-band`）とカテゴリラベル（`category`）が見分けられるか
   - 系列色が見分けられるか
6. `python -m pytest` を通してコミットする。系列色を実際の図で確認できたら、`chart.status` を `confirmed` にする。

既存テーマを、記録済みの種色から作り直すときは `python scripts/derive.py NN --force` を使う。記録済みの種色は採用済みとみなし、止まらない。

## 3. 基礎: 明度とコントラスト

### コントラスト比は明るさだけで決まる

WCAG 2.x のコントラスト比は (L1 + 0.05) / (L2 + 0.05) で、L1 が明るい方、L2 が暗い方の相対輝度。相対輝度 L は、sRGB を線形化した値から 0.2126 R + 0.7152 G + 0.0722 B で求める。色相は関係しない。

### 明度（トーン）

明るさは、見た目に近い尺度の CIE L*（0 = 黒、100 = 白）で扱う。相対輝度 Y から L* = 116 Y^(1/3) − 16 で求める。palette 名の数字（`brown-30` の 30）はこの明度。

明度の差から、確実に得られるコントラストが決まる。

| 明度の差 | 最低限のコントラスト |
|---|---|
| 40 | 3.17:1（線・図形・大きい文字の基準 3:1 を満たす） |
| 50 | 4.48:1（小さい文字の基準 4.5:1 にほぼ届く） |

白地（明度 100）の上で必要な明度は次のとおり。

| 用途 | 必要な明度 |
|---|---|
| 小さい文字（4.5:1） | 49.9 以下 |
| 線・図形（3:1） | 61.7 以下 |
| 7:1 | 37.8 以下 |

このため、**role ごとに必要な明度を決め、色相と彩度は種色から取る。** Google の Material Design 3 が HCT 色空間の「トーン」で行っているのと同じ考え方。

### 色空間

- **明度を変えるとき: OKLCH**（OKLab の極座標）で、色相と彩度を保ったまま明度だけを変える。
  - OKLCH は明度を変えても色味がずれにくい。HSL は「明度」が見た目の明るさと合わない（黄と青で大きくずれる）ので使わない。
  - 明度を変えると sRGB に収まらない場合は、彩度だけを下げる（色相と明度を優先する）。
- **色差: CIEDE2000（ΔE00）**。1 前後が見分けられる最小の差。
- **色覚の多様性: Machado ほか（2009）のシミュレーション**。1 型・2 型・3 型の 2 色覚（程度 1.0）について、色をシミュレーションしてから色差を計算する。

## 4. 種色の役割と基準

### 役割

配色の教本では、ベース 70%・サブ 25%・アクセント 5% の面積比がよく目安にされる。このリポジトリでは地の大部分が白なので、種色の役割を次のように当てる。

| 種色 | 役割 | 面積 |
|---|---|---|
| ベース | テーマの顔。ヘッダー帯・フッター帯の塗りと、強調の文字 | 色の付いた部分では最大 |
| サブ | 補助。帯の上の文字と区切り線 | 中 |
| アクセント | 目印。表紙のアクセントライン、セクション扉の縦バー | 少量 |

### 基準

種色は、主な用途で次を満たすこと。

| 種色 | 基準 | 根拠 |
|---|---|---|
| ベース | 白か本文色（明度 15）の文字に対して **7:1 以上**。明度でいうと **37.8 以下（暗い帯）か 71.8 以上（明るい帯）** | 理由は下の「ベースの基準が 7:1 である理由」 |
| アクセント | 白地で **3:1 以上**（明度 61.7 以下） | WCAG 1.4.11 Non-text Contrast（線・図形） |
| サブ | ベースに対して **4.5:1 以上** | WCAG 1.4.3 Contrast (Minimum)（帯の上の小さい文字） |
| 3 色どうし | 色差 ΔE00 **10 以上**（警告のみ） | 系列色と同じ目安（[7 章](#7-数値の一覧と根拠の強さ)） |

**ベースの基準が 7:1 である理由**

- 7:1 は WCAG 1.4.6 Contrast (Enhanced)（AAA）の基準。
- 帯には 2 種類の文字（`on-band` と `category`）を載せ、どちらも 4.5:1 以上で、しかも明度を変えて区別したい。
- 帯が中くらいの明度（例: 57）だと、4.5:1 を満たす文字は白にも明るい色にもならない。黒に近い色しか残らず、2 種類の文字がほぼ同じ色になる。
- 7:1 の余裕があれば、帯との差が小さい `category` と、差が大きい `on-band` を置き分けられる。

帯の明度と、帯の上で 4.5:1 を満たす文字の明度の関係は次のとおり。

| 帯の明度 | 文字の明度 |
|---|---|
| 25 | 67.6 以上 |
| 30 | 73.3 以上 |
| 35 | 79.5 以上 |
| 80 | 35.4 以下 |
| 85.5 | 39.6 以下 |

### 提案の作り方

基準を満たさない種色には、**同じ色相・彩度のまま明度だけを変えた色**を提案する。基準を満たす整数の明度のうち、元の明度に最も近いものを選ぶ（同じ距離なら暗い方）。

- **ベース**: サブが帯の上で読める側を優先する（サブが明るければ暗い帯にする）。
- **サブ**: ベースに提案があるときは、提案のベースに対して判定する。

例: ベース `#7A8B99`（明度 57）、サブ `#DDE6EC`（明度 91）の場合、ベースは明度 37 の `#495966` を提案する。暗い帯にすれば、明るいサブがそのまま帯の上で読める。

提案はあくまで案で、採るかどうかはユーザーが決める。採らなかった場合も、[5 章](#5-role-の割り当て)の規則で、文字に使う role だけ明度を変えた色を使うので、文字の基準は満たされる。

## 5. role の割り当て

基準（どの role をどの背景に対して何:1 で検査するか）は、[schema/theme.schema.json](../schema/theme.schema.json) の `x-contrast` にある。

「明度を変えた色」とは、種色の色相・彩度のまま明度だけを変えた色のこと。基準を満たす整数の明度のうち、種色の明度に最も近いものを選ぶ。

| role | 色 | 理由 |
|---|---|---|
| `background` | 白 | 印刷・投影で最も無難。図の背景とそろう |
| `text` | グレー、明度 15 | 白地で 15.2:1。純黒より柔らかく、ほぼ黒に見える |
| `text-secondary` | グレー、明度 40 | 白地で 6.46:1。本文との明度差 25 で補助だと分かり、4.5:1 にも余裕がある |
| `band` | ベース | テーマの顔 |
| `on-band` | サブ。帯の上で 4.5:1 未満なら、サブの明度を変えた色 | サブの役割 |
| `category` | ベースの明度を変えた色（帯の上で 4.5:1 を満たす、帯に最も近い明度） | 帯と同系色の控えめなラベル（トーン・オン・トーン） |
| `emphasis` | ベース → サブの順で、白地で 4.5:1 以上の種色。どちらも届かなければ、ベースの明度を変えた色 | 強調はテーマの顔の色で行う。明るいベース（例: ベージュ）ならサブ（例: ネイビー）になる |
| `accent` | アクセント（種色のまま） | 線・図形用。3:1 未満でも、提案を採らなければそのまま使い、警告を出す |
| `section-label` | アクセント。白地で 4.5:1 未満なら、アクセントの明度を変えた色 | 線より厳しい文字の基準を満たす |
| `rule` | 種色のうち最も明るい色 | 区切り線は装飾。目立たせない（情報を担わせない） |
| `placeholder-bg` | グレー、明度 97 | 白地との差が 1.08:1。白と見分けられる程度の面 |
| `placeholder-border` | グレー、明度 88 | 装飾。明度 97 の塗りの上で見える枠 |
| `placeholder-text` | グレー、明度 40 | 明度 97 の塗りの上で 6.0:1 |

**グレーにはベースの色相を OKLCH の彩度 0.006 だけ混ぜる。** 純グレーとの色差は ΔE00 で約 2〜3 で、並べると分かるが、単独ではグレーに見える程度。テーマ全体に温かみや冷たさのまとまりが出る。

**帯の上の 2 種類の文字が近すぎる場合の警告**: `on-band` と `category` の色差が ΔE00 10 未満になると、derive.py が警告する。サブとベースの色相が近いときに起こる。

## 6. グラフの系列色

**6 色作る。** 色だけで確実に区別できるのは 6 色程度までで、それ以上は線種・マーカーの形も使う（目安）。

**種色を先に並べる。** 順番は、`emphasis` に使った種色 → アクセント → ベース → サブ。

- 白地で 3:1 未満の種色は、明度を下げて使う。
- 既に選んだ色との色差が、どの見え方（一般色覚と 1〜3 型）でも ΔE00 10 未満なら外す。外したことは `notes` に書く。

**残りは追加色で埋める。** 候補は次の組み合わせ。

| 項目 | 値 | 理由 |
|---|---|---|
| 色相 | 5° 刻み | — |
| 明度 | 35〜60 | 60 以下で白地 3:1 以上。35 以上で本文色（明度 15）と区別できる |
| 彩度 | 種色の最大彩度を 0.10〜0.15 に収めた値 | 種色の鮮やかさに合わせる。収まらない色相では下げる |

候補の選び方は、Glasbey ほか（2007）の「既存の色との最小色差を最大にする」方法に、色覚の条件を加えたもの。

1. 色覚シミュレーション（1〜3 型）でも、既に選んだ色と ΔE00 12 以上離れる候補だけを残す。
2. その中で、一般色覚での最小色差が最大のものを 1 つずつ選ぶ。

**検査**: 全ペアの色差（どの見え方でも）が ΔE00 10 未満なら、check.py が警告する。

**状態**: derive.py が作った系列色は暫定案（`provisional`）。実際の図で確認したら `confirmed` にする。

## 7. 数値の一覧と根拠の強さ

| 値 | 使う場所 | 根拠 | 種類 |
|---|---|---|---|
| 4.5:1 | 小さい文字 | WCAG 2.x 1.4.3 | 規格 |
| 3:1 | 線・図形、大きい文字 | WCAG 2.x 1.4.11 / 1.4.3 | 規格 |
| 7:1 | ベース（帯） | WCAG 2.x 1.4.6。理由は 4 章 | 規格の値を流用 |
| 明度 15 / 40 / 88 / 97 | グレーの role | 5 章の理由 | 目安 |
| 彩度 0.006 | グレーに混ぜる色 | 純グレーとの差 ΔE00 約 2〜3 | 目安 |
| 6 色 | 系列色の数 | 色だけで区別できる数 | 目安 |
| 明度 35〜60、彩度 0.10〜0.15 | 追加の系列色 | 6 章の理由 | 目安 |
| ΔE00 10 | 色差の警告（系列色、種色どうし、帯の上の 2 種類の文字） | 線や点のような小さい印では差が見えにくくなるので、余裕を取った値 | 目安（実験で決めた値ではない） |
| ΔE00 12 | 追加の系列色の条件 | 警告の目安 10 に余裕を持たせる | 目安 |

目安の値を変えると、既存テーマの導出結果も変わる。変えたら次を行う。

1. 既存テーマで check.py を実行する。derived の再計算と一致しなくなり、エラーになる。
2. `python scripts/derive.py NN --force` で作り直す。
3. 差分とプレビューを確認する。

## 8. 検査の一覧（check.py）

**エラー**

- スキーマ違反
- 存在しない palette 名の参照
- 番号の重複・欠番
- roles のキーの不一致
- 種色（`seeds`）の不備
- 導出した色（`derived`）と hex の不一致

**警告**

- WCAG コントラストの基準未満
- 系列色どうしの色差が目安未満
- `notes` への記載漏れ

種色の判定と提案は、derive.py の出力と、README のテーマ一覧（「種色の基準」の列）に出る。

## 9. 限界

- **背景は白だけ。** ダークモードは扱わない。
- **見た目の良し悪しは判定しない。** 色相の調和（補色・類似色など）は見ていないので、プレビューで人が確認する。
- **色覚シミュレーションは近似。** 程度 1.0 の 2 色覚だけを見ている。
- **見本スライドの文字は英語。** プレビュー画像を、和文フォントのない環境でも崩さないため。
